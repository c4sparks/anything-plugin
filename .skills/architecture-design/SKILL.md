# 架构与功能设计

本项目的设计文档体系与编写规范（文档先行铁律）。

## 文档体系（各文档职责）

- `docs/架构设计.md`：整体架构、技术选型、模块划分、目录结构、关键决策。
- `docs/功能设计.md`：功能层面的思路、逻辑、交互——交互必须写到「操作 → 页面跳转 → 反馈」粒度，禁止概述式描述；说明取舍（为什么这么做）。
- `docs/详细设计.md`：逐文件实现设计（数据结构、接口、流程），作为编码依据。
- `docs/插件契约.md`：manifest schema / 运行时数据形状 / 校验规则 / 数据存储契约——**单一事实来源**，改契约先改本文档并升版本（版本演进记录在契约文档末尾）。
- `docs/开发规范.md`：开发铁律（文档先行、验证纪律、命名、安全）。
- `docs/设计规范.md`：UI/UX 设计契约（见 `ui-design` 技能）。

## 文档先行（铁律）

- 需求/方案确定后**先改文档再写代码**：功能层面写功能设计、逐文件实现写详细设计、契约改动先改契约文档。
- 文档是活的契约：代码与文档冲突时更新文档，而非放任不一致。
- 修改规范类文档本身也走流程（先记录变更，见 `record-changes` 技能）。

## 变更对应文档（改什么 → 更新哪份）

| 变更内容 | 对应文档 |
| --- | --- |
| 架构 / 技术选型 / 模块划分 / 关键决策 | `docs/架构设计.md` |
| 功能 / 逻辑 / 交互（操作→跳转→反馈粒度） | `docs/功能设计.md` |
| 实现细节 / 接口 / 数据结构 / 流程 | `docs/详细设计.md` |
| 插件 manifest / 数据存储 / 校验规则契约 | `docs/插件契约.md`（改契约须升版本） |
| UI 令牌 / 布局 / 组件规范 | `docs/设计规范.md` |
| 开发铁律 / 命名 / 安全 / 流程 | `docs/开发规范.md` |
| 插件开发流程 / 示例 | `docs/插件开发速查.md` |
| 功能清单状态 | `docs/功能清单列表.md` |
| 变更记录 / 问答决策 | `docs/changelog.md` / `docs/chat.md`（见 `record-changes`） |
| 构建 / 打包配置 / 命令说明 | `docs/详细设计.md` 打包章节 + `README.md` 命令表 |
| 验证流程与归档模板 | `test-verification` 技能（`tests/verification/` 只存产物） |

## 注意事项

- 交互粒度、契约版本规则的具体要求以各文档为准，本技能不复制内部细节。
