# 测试与验证

本项目的测试与验证规范：基线必须全绿；临时验证脚本与数据**必须留存**。

## 基线命令（改动完成前必须全绿）

- `pnpm typecheck`（node + web 双项目）
- `pnpm lint`（0 error；warning 需确认非本次引入）
- `pnpm test:unit`
- `pnpm build`（electron-vite build）
- 外部插件 entry.js 用 `node --check` 验语法

注意：typecheck 与 build 要**串行**执行——并行时 build 重写 `components.d.ts`/`auto-imports.d.ts`，vue-tsc 会读到半成品产生假报错。

## 临时验证（UI / 交互类）

- 用临时 Vite 工程独立渲染目标组件 + Playwright 断言；深浅两套主题都要验。
- 假 `window.api` 必须**镜像真实契约的校验规则**（如 `pluginData` 的 key 小写白名单），只镜像方法签名会漏掉校验类 bug。
- 临时工程目录用 `.tmp-*` 命名（已 gitignore），验证结束后可清理临时工程，但**脚本与数据保留**。

## 留存纪律（铁律）

**临时验证脚本与测试数据必须留存，测完不得删除**——便于回溯排障与复用。

### 目录结构（tests/verification/ 只存产物，规范在本技能）

```
tests/verification/
└── <YYYY-MM-DD>-<主题>/          # 每次验证一个子目录
    ├── README.md                 # 验证记录（字段见模板）
    ├── <验证脚本>.cjs/.mjs        # 脚本留存（可复用则沉淀为固定脚本）
    └── data/                     # 测试数据/产物（截图、断言输出、日志等）
```

### 验证记录模板（每个验证目录的 README.md）

```markdown
# 验证记录：<主题>

- 脚本功能：<这段脚本验证什么>
- 目的：<为什么做这次验证（对应哪个改动/反馈）>
- 执行命令：<可复现的命令>
- 执行时间：YYYY-MM-DD HH:mm:ss
- 数据：<关键数据点 / data/ 下的文件说明>
- 是否通过：✅ / ❌
- 问题备注：<发现的坑、假象、遗留>
```

### 规则

- 临时验证（临时 Vite 工程 + Playwright 等）：脚本与产物写入对应验证目录后**保留**，不删除。
- 时间字段一律精确到秒（年月日时分秒，本地时间），不允许只写到年月日/时分。
- 固定/可复用的验证脚本：留存并在后续验证中复用；沉淀为通用脚本时放 `scripts/` 或验证目录顶层。
- 每次运行都要更新或新增对应验证目录的记录（时间、数据、结果、备注），不得只留脚本不写记录。
- 验证环境的假 `window.api` 必须镜像真实契约的校验规则（只镜像方法签名会漏掉校验类 bug）。
- 临时工程目录用 `.tmp-*` 命名（已被 .gitignore 排除），验证结束后可清理临时工程，但**脚本与数据保留**。

## 常见坑

- 清理临时工程时 vite 子进程可能未释放文件句柄（EBUSY）：延迟重试，清理失败不判验证失败。
- 校验类验证的假实现必须带真实校验，否则"本地全绿、真机报错"。

## 变更对应文档

- 验证流程 / 归档模板 / 记录字段变化 → 本技能（约定统一在技能内，`tests/verification/` 只存产物）。
